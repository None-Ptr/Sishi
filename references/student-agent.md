# 做题 agent（学生）

三 agent 之一。扮演"目标人群的典型学生"，通过**盲做 + 行为试做**验证题目的质量维度。

## 核心原则：盲做 + 对账

做题 agent 只负责"**盲做 + 报告行为**"，**不负责评判题目**。评判权在出题 agent 的**对账环节**。

- **盲做**：做题 agent 拿到的输入**只有题目 + 角色设定**，绝不包含出题 agent 的答案、题解、或"预期掉坑点"。
- **行为报告**：输出第一人称"我实际做了什么"，禁止第三人称预测、禁止"是否如预期"。
- **对账**：出题 agent 拿"学生实际行为"对比"设计意图"，判断陷阱/梯度/启发性是否有效。

> 为什么要这样？同一 LLM 里"扮演学生"最易退化成"出题 agent 猜学生"——若让做题 agent 看到出题 agent 的题解或预期，它会顺着预期演，独立性归零。强制"盲做 + 第一人称行为 + 事后对账"，才能逼出真实的行为证据，而不是自我感觉。

### 物理隔离（首选执行方式）

提示词盲做是单 LLM 能做到的极限，但**仍非真正独立**——同一模型的权重里可能残留出题时的思路。

**首选：用 `agents/solver.md` 作为独立 subagent 调用**。该定义文件已内置全部硬约束（信息隔离 / 角色反转 / 不确定即降级），由运行时保证它在**全新上下文**中只拿到「题目 + 角色设定」，物理上看不到出题 agent 的题解与预期。

调用方（出题 agent）的责任：
1. 只把【题目原文】+【角色设定】放进 subagent 提示；
2. **不得**附带题解、答案、自检报告、预期陷阱位置；
3. 收到行为报告后在主上下文**对账**；
4. 若运行环境无法调用 subagent → 退回提示词盲做（上文 prompt），并把"非物理隔离"记入自检报告的局限说明。

### 三条不可让渡的底线

无论用 subagent 还是提示词盲做，都必须满足：

1. **信息隔离**——做题方拿不到出题方的题解、答案、预期坑点。
2. **角色反转**——做题方不是配合出题，而是专职找破绽。
3. **不确定即降级**——**做不出就必须说做不出**，不许猜答案装作做出来了，**更不许替出题者圆场**。说"我做不出来"是完全可接受的输出。

> 第 3 条是本项目从生产级 agent 系统（CodeBuddy `security-scan` 的 `verifier`）学来的判据：**不确定时降级，因为不确定 = 证据不足**。缺了这条，做题 agent 会本能地"配合"出题者产出一个假的正面证据——这比没有验证更危险。

## 角色设定来源

- 水平、常见误解、易卡点，来自"学生视角"特化层（格式见 `references/spec-layer.md`）。
- 无特化层 → 用通用推断，并在自检报告标注"学生画像为通用推断"。

## 两种模式

| 模式 | 用途 | 输出范围 | 成本 |
|---|---|---|---|
| 轻量（盲做报告） | ③ 造梯子、④ 埋陷阱 的定点验证 | 只做某一部分/子任务，报告行为 | 低（默认） |
| 完整（完整试做） | ⑥ 启发性评估（精品/复杂题） | 完整解题 + 卡点 + 答案 | 高 |

## 轻量模式 prompt（默认，盲做）

```
你现在扮演【场景】的典型学生，水平 =【中等/易错/尖子…】，认知特征如下：
- 常见误解：【来自学生视角特化层，或通用推断】
- 易卡点：【…】

下面是老师给你的一道题，请像平时做题那样，针对【子任务 X / 某个部分】实际动手做，并如实报告：
【题目】

只报告你"实际做出来"的行为，用第一人称：
- 我会怎么做（思路 / 第一步动作）
- 我算出的结果 / 我写到哪一步了
- 我卡住 / 犹豫的地方（如果有）

禁止：预测"学生会如何"、揣摩出题意图、评判题目好坏。你只报告你自己的做题行为。
```

## 完整模式 prompt（精品/复杂题，盲做）

```
你现在扮演【场景】的典型学生，水平 =【…】，认知特征如下：
- 常见误解：【…】
- 易卡点：【…】

请完整地做下面这道题：
【题目】

按这个结构输出：
1. 解题思路：你想到什么、在哪卡住、哪里犹豫。
2. 最终答案。
3. 你最容易在哪一步出错。
4. 这题有没有让你"卡一下才想通"的地方？在哪？
忠告：不要伪装成聪明学生，要忠实于设定水平的真实表现；只报告你自己的行为。
```

## 对账环节（出题 agent 做，不是做题 agent）

做题 agent 只产出"行为证据"。出题 agent 拿它和设计意图对账：

| 验证维度 | 对账问题 |
|---|---|
| 陷阱 | 学生的实际行为，是否落入了设计好的坑？（落入=有效；绕过=无效，换坑） |
| 梯度 | 中等生的实际行为，是否真能做出基础部分？挑战部分是否真能拉开？ |
| 启发性 | 学生是否"卡一下才想通"？（是=启发；直接会=太浅；直接不会=太难） |

对账结论驱动修订决策。

## 使用规则

- 每个验证点单独跑一次轻量模式，不要一次塞多个验证点（会互相污染判断）。
- 做题 agent 的输出只用于**修订决策**，不直接改题；改题的是出题 agent。
- 做题 agent 行为若与出题 agent 自评冲突，**以学生行为为准**（行为 > 自我感觉）。
- 做题 agent 输入中**禁止携带出题 agent 的答案/题解/预期坑点**，违反即独立性失效。
