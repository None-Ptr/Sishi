# 蒸馏器

把用户提交的材料蒸馏成**场景特化层**，供三个 agent 各自复用。

## 触发时机（混合）

1. **显式**：用户说"蒸馏这套教材 / 提炼这些真题的出题思路 / 分析这些错题"。
2. **自动命中检测**：出题诊断阶段检查当前场景有无特化层，没有就轻量提示（可跳过）。
3. **建议特化**：出题后若用了通用兜底，主动提示一次"可提交材料蒸馏，下次更准、更防超纲"。

## 四维度映射（分别蒸馏）

| 维度 | 谁用 | 输入材料 | 蒸馏产物 |
|---|---|---|---|
| 知识点边界 | 共享约束 | 教材 / 大纲 / 课程进度 | 能考什么、不能超什么纲 |
| idea 视角 | Idea agent | 经典好题 | "什么点子算好题眼"、灵感来源 |
| 出题视角 | 出题 agent | 真题 / 出题人作品 | 落地手艺、题型取舍、难度梯度 |
| 学生视角 | 做题 agent | 错题 / 学生画像 | 典型水平、常见误解、易错点 |

四个维度独立蒸馏、独立更新：**提交什么、蒸馏什么**，不强求一次给全。

## 蒸馏流程

1. 读入材料，判断它属于哪个维度（多材料可映射多个维度）。
2. 按维度提取可操作框架——不要复述材料内容，要提炼"判断标准 / 决策启发式"。
3. 落盘到特化层（格式见 `references/spec-layer.md`）。
4. 回执给用户：蒸馏出什么维度、覆盖了什么。

## 存放位置

- **特化层是数据，绝不写进 skill 目录**（升级会覆盖丢失）。
- 可配置指向任意位置（团队可 git 共享）。

### 路径解析（首次运行时确定）

在**首次需要读写特化层时**解析一次，之后复用。**对每个候选路径先做写入探测**（尝试建目录并写一个 `.probe` 文件），不可写就记下原因并试下一个：

| 顺序 | 候选 | 说明 |
|---|---|---|
| 1 | `<skill 目录>/sishi.config.json` 的 `specLayerDir` | 项目级，**可随仓库git 共享**（团队首选） |
| 2 | `<用户主目录>/.sishi/config.json` 的 `specLayerDir` | 用户级，跨项目复用 |
| 3 | `<用户主目录>/.sishi/特化层/` | 无配置时的默认位置 |
| 4 | **仅读兜底** | 全部候选都不可写 |

- 相对路径以**配置文件所在目录**为基准。
- **所有候选均不可写** → 进入仅读兜底：**不写盘、不建目录**，并明确告知：
  > 特化层路径不可用（依次尝试：项目配置 → 用户配置 → 用户默认目录，均失败）。本次走通用兜底，**不会保存任何特化产物**。修复方式：把 `specLayerDir` 指向一个**可写目录**（项目内路径需确保目录已存在且当前用户有写权限），或删除损坏的配置项改用默认位置。
- **必须区分"没有特化层"与"特化层不可用"**：前者按"缺维度兜底"处理并建议特化；后者必须额外提示"配置有误/权限不足"，**禁止静默假装已特化**。

**首次运行必须问用户一次**（仅当路径未确定且存在多个合理选项时）：

> 特化层要存在哪里？
> - A. 用户主目录 `~/.sishi/特化层/`（推荐，个人跨项目复用）
> - B. 当前项目内（团队可 git 共享，但仅本项目可用）
> - C. 自定义路径

得到答复后写入对应位置的 `sishi.config.json` 落盘，后续运行不再询问。用户未选或无写入权限 → 进入仅读兜底，并在出题时按"缺维度兜底"处理。

## 缺维度兜底

- 出题时缺某个维度 → 用通用底座兜底，照常出题。
- 自检报告诚实标注"该维度为通用推断、非场景特化"。
- 主动建议特化（一次提醒，不强迫）。
