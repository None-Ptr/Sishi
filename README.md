# 司试（Sishi）

> 通用出题 skill。借鉴 nuwa-skill「蒸馏认知框架而非知识」的思路，用**三个 agent 协同**产出有启发性、质量可验证的题目。

解决的是 AI 出题的两个老毛病：**无启发性**（知识点平铺、套模板即得、做完没收获）与**质量差**（表述歧义、答案出错、难度失控、无区分度、超纲）。

---

## 承诺边界（先读这段）

| | |
|---|---|
| ✅ **能兑现** | **针对特定误解的个性化原创**——「你总漏反向边，所以我造一道必须同时处理正反两向的题」。依赖学生误解档案（`学生视角` 特化层），难以手工做到。 |
| ❌ **不能兑现** | **历史性原创**（首创新题）——依赖训练数据之外的新工具、新竞赛趋势、真人经验。LLM 原理上给不了，硬逼只会产出「看着新、实为经典变体」的题。 |

所以司试不追求**首创**，追求**陌生** + **对症**。判「经典复刻」的闸门见下方`references/engine.md` ② 的**经典度判负**。

---

## 架构

### 三个 agent（分别蒸馏）

| agent | 职责 | 蒸馏维度 | 文件 |
|---|---|---|---|
| **Idea agent** | 发散题眼 / 创意（只发散，不评判、不写完整题） | `idea 视角`（题眼审美） | `references/creativity.md` |
| **出题 agent** | 把idea 落地成严谨的题 | `出题视角`（落地手艺） | `references/engine.md` |
| **做题 agent** | 盲做验证，产出行为证据 | `学生视角`（学生画像） | `references/student-agent.md` |

**为什么要拆三个？** 出题最缺的不是「把题写严谨」，而是「想到一个好点子」。想点子时追求新奇会破坏严谨，落地时追求严谨会掐死创意——混在一个 agent 里两者互相压制。拆开，各司其职。

### 六步元流程（通用底座）

```
① 锚定考察目标 → ② 设计题眼 → ③ 造梯子 → ④ 埋陷阱 → ⑤ 反向自检 → ⑥ 启发性评估
```

每步都有**判负标准**（判负即返工，不许将就）：

- **① 锚定** 目标含糊 / 人群错配 / 目标超纲 → 判负
- **② 题眼** 三档：知识点平铺 = 无题眼（判负）；强题眼须再过**经典度判负**
- **③ 造梯子** 梯度塌缩（无区分）/ 梯度断裂（基础太难）→ 判负
- **④ 埋陷阱** 无诱导性（谁都不会掉）/ 有争议（这是坏题不是好陷阱）→ 判负
- **⑤ 反向自检** 6 条硬指标：题设充分 / 答案唯一 / 无超纲 / 无歧义 / 约束自洽 / 样例有效
- **⑥ 启发性** 弱 / 中 / 强三档

### 关键机制

**盲做 + 对账（反「LLM 自评不可靠」）**
LLM 出完题自己夸自己是最常见的失效。司试让做题 agent **盲做**——输入只有「题目 + 角色设定」，**严禁携带出题 agent 的答案、题解、预期坑点**，只准输出第一人称行为报告（「我算出了什么、我卡在哪」），禁止「学生会如何」的第三人称预测。**判断权不在做题 agent，在出题 agent 的对账环节**。

> 同一 LLM 里「扮演学生」极易退化成「出题者猜学生」。若运行环境支持子agent（Task 工具），优先用**独立 subagent** 跑做题 agent 实现物理隔离；不支持则退回提示词盲做，并在自检报告标注「非物理隔离」。

**输出契约（五件套）**
题目 + 答案 + 题解 + 自检报告 + **深挖失败记录**。

第五项是本项目的独特设计：记录出题过程中**尝试过但证伪/放弃的方向**。放弃路线但保住难度与严谨性 = 健康（如实写出，是原创性的正面信号）；放弃后把题做水 = 判负。一题无失败记录**不加分**——立刻找到漂亮闭式往往说明只是复刻了熟悉结构。

## 特化层：四个维度，分别蒸馏

一个场景 = 一个目录，四个**可选**维度文件：

```
特化层/
└── 初三数学/                # 场景名 = 命中检测的索引键
    ├── 知识点边界.md        # 共享约束：能考什么 / 超纲红线 / 认知层次上限
    ├── idea视角.md# Idea agent：什么点子算好题眼、灵感来源
    ├── 出题视角.md          # 出题 agent：落地手艺、题型取舍、难度梯度
    └── 学生视角.md          # 做题 agent：水平分布、误解清单、易卡点
```

- **四维度独立蒸馏、独立更新**：提交什么、蒸馏什么，不强求一次给全。
- **存储**：默认全局数据目录，可配置指向任意位置（团队可 git 共享）。**特化层是「数据」，绝不写进 skill 目录**（升级会覆盖丢失）。
- **缺维度兜底**：用通用底座继续出题，但自检报告必须诚实标注「通用推断、非场景特化」。

### 三条铁律

1. **特化层是数据，skill 是代码** —— 绝不写进 skill 目录。
2. **通用底座必选，特化层可选** —— 没特化层也能出题，但必须诚实标注兜底。
3. **主动建议特化，不静默兜底** —— 用了通用兜底就提示用户可提交材料蒸馏，但**一次出题最多提醒一次**，不强迫、不唠叨。

### 特化层路径

首次需要读写特化层时，司试会问一次，存在哪里：

```
特化层要存在哪里？
- A. 用户主目录 ~/.sishi/特化层/   （推荐，个人跨项目复用）
- B. 当前项目内                （团队可 git 共享，但仅本项目可用）
- C. 自定义路径
```

选择后写入 `sishi.config.json` 的 `specLayerDir`，后续不再询问。未配置且不可写时退化为**仅读兜底**，出题时按"缺维度"处理并明确告知。

## 用法

装到对应平台的 skills 目录（Claude Code: `~/.claude/skills/sishi/`）后，自然语言触发：

```
出几道动态规划题，最近只会套模板，想练练手
帮我出套卷子，目标是省选水平
蒸馏这套教材，做成出题视角
分析这些错题，提炼学生视角
```

**触发**：出题 / 构造题 / 生成练习题 / 蒸馏方法论与画像。
**不触发**（主动让位给解题类 skill）：讲题 / 解题 / 审题 / 批改。

### 运行环境要求

- **完整能力（推荐）**：运行时需支持独立 subagent（如 Task 工具），做题 agent 才能物理隔离（`agents/solver.md`），独立性最强、行为证据最可信。
- **降级模式**：不支持 subagent 时退化为提示词盲做，自检报告会标注「非物理隔离」，独立性打折但出题流程仍可用。
- **如何接入 sub-agent**：不同平台（Claude Code / CodeBuddy / Cursor 等）放置 `agents/solver.md` 的方式不同，见 [`references/subagent-setup.md`](references/subagent-setup.md)。

## 局限

- 模型推理天花板：答案与题解的正确性最终受限于底层模型会不会做这道题，反向自检是启发式对勾，不是数学证明。
- 做题 agent 的独立性依赖运行环境：没有独立 subagent 时只能提示词盲做，独立性打折。
- 陌生度 ≠ 首创：修完经典度判负后，产出大概率仍是见过的骨架换个载体，但更难一眼认出母本。真正陌生的骨架靠`学生视角` 特化层里那份真实的误解档案。
